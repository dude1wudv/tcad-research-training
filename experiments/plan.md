## 1. 研究目标与问题

核心目标是建立可信的多特征尺寸 DRAM 单粒子效应评估链路，实现自然语言参数遍历、Geant4→TCAD 传递，以及效应拟合、外推与验证。以下问题先作为方案目标，具体观察量和假设在模型交接后冻结：

- P1：在明确定义的尺寸/工艺与粒子条件下，哪些单粒子响应发生了怎样的变化，结论适用于什么范围？
- P2：Geant4 事件怎样转为 TCAD 激励，坐标、单位、离散化和维度处理是否通过检查？
- P3：自然语言请求能否准确转为获准工况并完成可追溯运行，歧义或越界请求能否被识别？
- P4：拟合模型在域内留出工况和域外工况上误差如何，能否经独立真实仿真或可用参考数据验证？

需求 R1–R8、候选指标与证据见[实施路线](roadmap.md)。优先回答 P1–P4；以下 RQ1–RQ4 是保留的可选 AI 效率研究，不替代核心物理与预测任务：

- RQ1：在质量要求相同的前提下，自动化是否减少人工操作时间与干预次数？
- RQ2：AI 相比固定脚本，是否能更有效地提出参数试验、解释失败并形成可验证的下一步？
- RQ3：全过程能否追溯到模型、参数、工具版本、原始输出和人机决策？
- RQ4：AI 能否识别未收敛、错误条件及证据不足，而不是把运行完成误当结果正确？

以上均为待检验问题，不预设 AI 一定优于人工或脚本。若题目不包含优化任务，则将“迭代”限定为满足要求的建模修订、扫描或收敛诊断，不额外创造器件性能优化指标。

## 3. 可选 AI 效率对照设计

### 3.1 三组及其边界

| 组别 | 操作方式 | 决策来源 |
|---|---|---|
| A 人工组 | 人工执行原生软件操作、查看日志并整理结果 | 学生依据统一资料决策，不使用 AI 建议 |
| B 固定脚本组 | 预先冻结的参数扫描、运行、提取和检查脚本 | 固定规则；运行中不使用 AI 动态改参 |
| C AI 辅助组 | 相同原生工具及基础执行组件，AI 读取允许证据并提出下一步 | 指定模型提出建议；按预授权范围执行或经人工审批 |

人工组可使用统一的只读记录工具，避免测量手段本身制造差异。若 B 组脚本由 AI 协助开发，须披露；B 组仍指运行时无 AI 决策，而不是开发过程从未使用 AI。

C 组计划使用 OpenAI OAuth `openai-codex/gpt-6-astra:medium`，记录实际运行模型、推理等级、提示词版本和可获取的调用统计；不可获得的费用/Token 信息记为“不可获取”，不估造。

### 3.2 分开评估两个层次

**层次一：相同任务执行。** 各组完成相同的预定工况、同等图表和证据要求，比较操作、后处理、归档的效率与正确性。不允许 C 组通过少做工况获得时间优势。

**层次二：有限预算迭代。** 仅在题目允许且目标明确时开展。各组从同一初始工程出发，在相同求解调用预算、允许参数空间和停止条件下寻找满足标准的结果。各组可以选择不同参数点，但必须记录全部尝试及失败。

完整 A/B/C 和第二层迭代属于扩展研究，不是完成课程的前置条件。默认先完成一个通过质量门槛的教师题目基线和教师要求的实验，再依据预算审核决定对照规模：完整三组；或只比较 B/C 的配对任务（结论仅限 AI 相对固定脚本）；或仅记录 AI 辅助案例（不作相对效率和因果优势结论）。缩减须在正式比较前批准，不能事后以单组演示替代对照研究。

### 3.3 控制混杂因素

- 相同输入版本、TCAD 版本、VM 资源、许可证条件、求解核数和质量门槛。
- 当前沿用单任务单核与串行依赖；不同时运行别的求解任务。
- 共用数据处理公式和单位约定；先通过独立检查确认公式正确。
- 共用环境初始化不计入某一组独有耗时；组别专属开发、提示词准备及调试成本单独报告。
- 每次从明确的初始状态开始，不复用他组中间结果或缓存来缩短耗时。
- 用配对任务及轮换/随机顺序降低练习和顺序效应，记录操作者与运行顺序；同一学生学习效应无法完全消除时明确列为局限。
- 重复次数根据试运行成本事先确定。单次演示不能证明稳定收益，也不适合显著性结论。

## 4. 受控迭代闭环

题目与目标 → 参数/权限检查 → 提案 → 人工审批或预授权 → 实际仿真 → 工程验收 → 物理检查 → 自动提取 → 下一轮/停止 → 报告归档。

每轮分别保存：

1. 当前输入版本、待解决问题和已有证据。
2. 候选改动、依据、预期效果及风险；区分物理参数变化与数值设置变化。
3. 提案来源、审批/拒绝与理由。人类修改 AI 提案也算人工干预。
4. 实际执行参数、命令、run ID、输入哈希与运行状态。
5. 求解结果、有效性判断、提取值与下一步依据。

自动执行只限于事先批准的参数和值域。结构、材料、物理模型、边界条件、许可证、系统配置等变更不随普通扫描自动放行。

停止条件在正式实验前填写具体阈值：目标满足、调用/时间/费用上限到达、预定轮数无有效进展、重复同类失败、越界提案或环境不可用。中断后先核对远端进程和运行目录，禁止盲目重复提交。

| 数值与事件统计 | 网格、时间步、事件采样的设置及敏感性；报告实际误差范围，不预设事件数足够 |
| 改参正确性 | 自然语言请求、结构化参数、输入差异和实际运行条件相符；记录有效与拒绝案例 |
| 预测质量 | 域内留出与域外验证分开报告；数据按工况分组防泄漏，记录基准模型、误差指标及适用范围；无参考实测时不宣称实验校准 |

本表是定义要求，不是已经通过的指标。具体接口检查、数据划分和验收材料见[实施路线第 3–4 节](roadmap.md)。

### 5.2 可选流程效率指标

| 指标 | 定义与记录方式 |
|---|---|
| 人工操作时间 | 人实际操作、阅读、判断和修正的活动时间；审批和干预计入，机器等待另列 |
| 端到端时间 | 从冻结任务输入交给该组到满足交付标准的墙钟时间；包括失败恢复及 AI 等待 |
| 准备成本 | 组别专属脚本开发、提示词、调试时间；与重复运行成本分别展示 |
| 人工干预次数 | 开始执行后，为纠正、审批或恢复而发生的独立人为决策/操作事件；连续解决同一问题按一个事件并记录时长 |
| 有效运行率 | 通过预定工程与物理门槛的尝试数 / 全部已启动尝试数；同时给出整数计数和失败类别 |
| 任务完成率 | 满足全部交付标准的任务数 / 已分配任务数，避免“未启动”从有效运行率分母消失 |
| 迭代效率 | 达到预定目标所需求解次数及墙钟时间；预算内未达到标记未达成，不伪装为达到上限时成功 |
| 结果一致性 | 相同物理输入下的关键标量/曲线误差；容差事先固定，近零参考量使用绝对误差或预定尺度，不随意除以零 |
| 证据完整率 | 有效证据项目数 / 预先定义的必需项目数；内容匹配才算有效，不以空文件存在计分 |
| 故障处理质量 | 是否识别、是否正确分类、是否安全停止/恢复、额外人工干预和恢复时间 |
| AI 调用成本 | 实际可获取的请求数、Token、等待时间及费用；与求解时间分开 |

报告原始计数、配对差值、适用时的中位数和范围。小样本以描述性结果为主；不预先承诺统计显著性。基础设施故障单独标注但不从总过程隐去；若另报排除环境故障的分析，须同时展示未排除结果和排除规则。

## 6. 结果质量门槛

- **运行层：** 命令、工具与归档状态可追溯；退出码、日志及产物相互一致。
- **数值层：** 真正收敛至目标工况；数据完整且有限，接触、偏压、温度与单位正确。
- **物理层：** 依据最终题目检查守恒、趋势、边界、模型适用性，以及网格/步长敏感性。
- **呈现层：** 图件来自对应原始解，变量与单位正确，截图不冒充数据验证。

运行器的 `COLLECTED` 只表示执行/归档完成，不能直接作为物理层通过标记。人工组、脚本组和 AI 组采用同一质量门槛；不能用降低质量换速度。

## 7. 可选受控故障实验

在正常工况跑通后、独立副本中执行；不破坏用户 VM、真实许可或正式数据。

| 故障场景 | 预期安全行为 | 边界 |
|---|---|---|
| 缺少输入文件 | 识别具体缺失项，停止并保留日志 | 仅移走实验副本中的文件 |
| 越界参数提案 | 执行前拒绝并解释约束 | 不把危险值实际送入求解器 |
| 未收敛或未达目标工况 | 不标有效，区分数值调整和物理变更 | 使用受控案例或已存在失败证据 |
| 结果缺字段/文件截断 | 后处理拒绝产出正式结论 | 操作输出副本，保留原始结果 |
| 连接中断 | 不盲目重复求解，先查询远端状态 | 仅在可隔离且得到明确授权时注入 |

故障注入矩阵、判分标准和允许恢复动作在执行前固定。不主动破坏许可证服务；历史许可故障可作案例，但不能冒称受控重复试验。

## 8. 证据与实现分层

- `experiments/`：本方案及按已下发题目冻结的实验定义、参数空间和对照安排。
- `simulation/`：版本化模型，资格测试与正式题目工程分开。
- `scripts/`：复用现有启动、连接和运行入口，不建立第二套 runner。
- `tests/`：操作测试与受控故障案例，不冒充正式研究结果。
- `local_runtime/`：完整原始运行和日志，不入库；敏感信息不进入报告。
- `reports/`：报告正文、已审核小型图表和证据索引。
- `design-notes/`：经验证可复用的经验。

每条运行记录计划包括：任务/组别/重复编号、run ID、输入版本及哈希、模型与提示词版本、修改参数、决策/审批、起止时间、命令、退出码、失败分类、质量判断、指标和原始证据位置。此处定义的是拟采集要求，不声称现有程序已经全部自动采集。

### 9.1 阶段门：每步都有输入、动作和产物

### 9.2 最小可交付与扩展实验

- **项目设计核心包：** 教师认可的方案、可行性与进度、2～3 人实际分工；有来源的多尺寸 DRAM/Geant4/TCAD 模型；真实事件传递与数值/物理检查；工艺/粒子/方向扫描；效应拟合、域内及外推验证；总结报告、PPT/作品演示和来源索引。具体工况数量、字数与格式由教师确认。
- **必做 AI 辅助功能：** 自然语言到两端模型参数遍历的真实案例，保存“请求—参数—检查—执行—验证”记录，披露模型与学生贡献。单案例先证明流程可行，最终仍需覆盖上述核心包；不宣称 AI 优于人工或脚本。
- **兼报科研训练时：** 另满足第 0.2 节的阅读、字数、专题演讲与过程要求；该课程评分独立计算。
- **扩展包：** A/B/C 配对比较、有限预算优化、受控故障、额外复现。仅在核心包可按期完成、正式预算冻结且权限允许时添加。

### 9.3 TCAD 可执行入口与模型变更顺序

1. 建立唯一题目代号，在 `simulation/` 下创建独立正式工程。路径名称由任务卡记录；不可覆盖 `simulation/qualification/`，也不可仅给 PN 基准改名就声称匹配新题目。
2. 冻结原始输入并维护 `project.json`：声明实际工具、参数与每步预期输出。参考 [工程清单](../simulation/qualification/pn-diode/project.json) 的格式，但结构、文件名及步骤必须按正式题目设置；SDE 内调用网格生成还是单独 snmesh，以实际工程为准。
3. 若教师要求 Workbench 原生项目，先保存原生工程、参数表和节点依赖。当前 runner 不解析 `@node@` 等占位符；不能拿普通 deck 或空白 Workbench 代替原生节点运行证明。此要求必须在 G0 识别，并在 G2 验证对应路径。
4. 复用现有入口，不写第二套运行器：

   ```powershell
   # 在仓库根目录执行；保留现有会话，不启动源镜像。
   pwsh -File scripts/start-vm.ps1
   # start-vm.ps1 已调用 doctor；独立复查时才需要下一条。
   python scripts/tcad.py doctor
   # 将 <题目代号> 替换为任务卡的真实目录名，准备完 G0–G4 后执行。
   python scripts/tcad.py run simulation/<题目代号>
   ```

   `doctor` 探测会签出/签入许可证，但不是实际求解、物理校准或原生 Workbench 调度验证。

5. 按“结构/材料/接触 → 掺杂/网格 → 平衡初始化 → 教师要求的偏压/工况 → 提取”推进。物理模型、边界及结构变更先审核；允许的参数扫描优先单因素。不要跳过平衡初始化直接大范围扫描。
6. 使用当前单核、单线程、锁和独立 run 机制。完整日志/原始 TDR、PLT 保存在 `local_runtime/`，只将审核后的必要小型图表和汇总放入报告。
7. Visual 必须加载目标 run 的实际结果，核对变量、单位、工况和色标；截图只是 GUI 证据。已有 [电场脚本](../tests/pn-field-desktop/field.tcl) 仅可作 API 示例，不无条件复用 PN 文件名、变量或电场峰值。

### 9.4 数值验证和预算安排

先用最小有效工况测得单次耗时，再制定真实运行预算。网格/步长验证选择题目关键输出和最敏感工况；可先对基准与加密设置做配对比较，差异未满足事先审核的绝对/相对容差时继续加密。两套设置接近不等于严格网格独立，报告必须给出实际设置、差值和未覆盖区域；容差不能事后随结果放宽。

计划调用数至少计入：基线与数值验证 + 各组工况×重复次数 + 批准的迭代上限 + 失败恢复储备。不同工况/阶段耗时不同，应分别估算，不将一次极短基线当作所有扫描成本。总预算含模型/API等待、日志检查、提取、写作和演讲准备；临近截止先停止可选扩展，不以省时间为由跳过核心质量检查。

原**科研训练课程**总计 32 学时，教学安排为检索 4、阅读 12、合作写作 8、专题演讲 8 学时（第 3 页），仅在确认兼报时采用下表；项目设计大纲未给出这一学时安排。当前项目的建议相对进度、依赖与分工见[实施路线第 5–6 节](roadmap.md)，不能保证整套联合仿真只用 32 学时：

| 课程安排 | 本项目对应活动 | 必须留下的材料 |
|---|---|---|
| 检索 4 学时 | 检索式、数据库与筛选、来源核实 | 检索日志和候选资料清单 |
| 阅读 12 学时 | 中英文各至少 10 篇阅读、归纳问题/模型/参数 | 阅读矩阵和来源表 |
| 合作写作 8 学时 | 小组讨论、结果审查、报告整理与修订 | 分工、讨论记录与报告版本 |
| 专题演讲 8 学时 | 制作 PPT、试讲、演讲/答辩、反馈 | PPT、试讲问题与正式反馈 |

建模、运行和追加验证的实际时间另列，课外工作不伪装为课程已安排学时。具体日历在 G0 依据截止时间确定，并给最后审核与演讲留出缓冲。

## 11. 文献到实验设计的衔接

1. 题目已下发，用“器件/材料 + 目标物理量 + 物理机制 + TCAD/model/validation”等中英文关键词检索；当前题目还需覆盖存储器/DRAM、Geant4 辐照输运与单粒子效应等方向。优先学校数据库、原始期刊/会议论文、可信专利和合法工具资料，保留数据库、检索式与日期。
2. 按模型、参数、接口和验证的实际证据需求选择中英文资料，覆盖 DRAM/单粒子机理、Geant4 输运、TCAD 模型、耦合方法及预测验证。项目设计大纲未规定篇数；确认兼报科研训练时满足中文、英文各至少 10 篇的阅读要求。AI 自动化资料不能挤掉器件物理阅读。
3. 建立阅读矩阵：文献 ID；完整题录/DOI或链接；语言；研究问题；方法/结构/条件；主要结论；局限；可用于本项目的参数/模型/对比；原文页码或图表位置；学生阅读日期与评价。
4. 对同一结论比较多篇来源，区分实验测量、作者仿真与综述转述。不能把不同温度、维度、面积/宽度归一化或模型条件下的曲线直接当同等参考。
5. 输出三项可执行决定：研究缺口与问题；建模参数/假设来源表；参考质量判据。AI 可辅助搜索词和归纳，学生核对原文、数值、单位和引用。
