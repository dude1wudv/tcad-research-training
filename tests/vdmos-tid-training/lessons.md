# 本次问题与处理记录

仅记录真实出现的问题；不编造尚未发生的收敛失败。逐项按场景→证据→原因→处理→验证→适用边界组织。

## 1. 论文PDF有链接但不能读取正文

- 场景：读取UCF VDMOS学位论文馆藏及下载链接。
- 证据：馆藏页正常返回题录/摘要，`cgi/viewcontent.cgi?article=6137&context=etd`返回HTTP403。
- 原因：下载访问被拒绝，无法证实具体机制；不是已读到全文。
- 处理：把该来源标为“仅摘要”，改用可获取的VDMOS原文、公开工具教程与明确标注的训练参数，不从摘要臆造尺寸/掺杂。
- 验证：已实际读取Bella/Ghoumazi2022全文、Gao2012原始页面及Schwank机制/公式；详见literature.md。
- 适用边界：文献访问失败不能转化成参数事实，也不能把其他工艺的数据无条件迁移。

## 2. 中文PDF文字提取乱码

- 场景：Gao2012论文全文文字提取出现大量无意义符号，尤其第3–4页。
- 证据：阅读工具明确提示提取不完整；保留开放论文PDF及SHA256。
- 原因：[推断] PDF嵌入字体/编码不利于纯文本提取。
- 处理：下载原PDF到被忽略的运行资料目录，用独立主机分析环境的PyMuPDF渲染第2–3页，再直接查看实际图片。
- 验证：实际读到第2页图1与表3、剂量Gy(Si)/偏置/退火，第3页阈值与击穿曲线。澄清论文的整芯片1mA判据不同于本次A/µm定义。
- 适用边界：不以乱码文本做精确数值引用；原文图中不同条件要一起读取。

## 3. 主机Python禁止全局安装

- 场景：执行`%pip install numpy matplotlib pymupdf`。
- 证据：返回`externally-managed-environment`，提示Python由uv管理。
- 原因：PEP668保护受管理环境。
- 处理：不使用`--break-system-packages`；在`local_runtime/vdmos-analysis-venv/`创建独立venv，在其中安装可信分析依赖。没有改客户机TCAD、OS或许可证。
- 验证：venv内pip退出0，PDF实际渲染成功；后续数据脚本使用该venv解释器。
- 适用边界：venv是本机运行材料，不入库；复用时依赖版本另外记录，不能假设系统python拥有同一依赖。

## 4. 实际代理配置不可指定

- 场景：用户允许多个slow gpt-6.1-sol，不允许普通Luna执行高难工作。
- 证据：可用代理接口只接受预定义agent名称，没有显式model/slow设置；stateless completion有slow别名但不能证明对应模型并不具备工具操作。
- 处理：复杂物理建模、实际运行和文档由当前gpt-6.1-sol主Agent负责，不把名称写进提示词就当切换成功。普通worker仅可用于明确的低复杂度数值/解析测试，不做电脑操作、物理方案或报告。
- 验证：本次未派发上述高难任务给普通worker。
- 适用边界：如果之后提供可核实的slow代理配置，可并行只读调查；仍保持每文件唯一写入者与单求解串行运行。

## 5. 电流安全停止不是“缺少 Curve trace finished”

- 场景：pilot 的击穿归档成功，但首版后处理要求每个 log 都含 `Curve trace finished`，实际复现抛出 `Missing trace completion in breakdown_des.log`。
- 证据：同一真实 log 有 `Contact current exceeded limit:`、端电流超过冻结的 `5e-6 A/µm`、正常写出 TDR 与 `Sentaurus Device simulation finished`，执行/归档退出均为0。
- 原因：后处理把正常扫到终点与用户声明的电流安全停止混为一种完成方式。
- 处理：只有击穿路径允许已声明的安全停止，同时仍要求工具正常完成和 PLT 实际终点满足安全电流或电源目标；不接受任意中断。
- 验证：保留失败复现，修正后同一pilot归档通过；测试同时覆盖电流守恒失败和真实安全停止，不重跑或修改原始解。
- 边界：`COLLECTED` 本身不足以证明偏置路径有效，更不能把未收敛终点当BV。

## 6. 阈值横轴与“第一个点”都有真实含义

- 场景：栅 `Barrier=-0.55`，PLT 的 gate InnerVoltage 比 OuterVoltage 多0.55 V；`NewCurrentPrefix=\"idvg_\"` 后第一个输出点的外加栅压不是0。
- 证据：pilot前缀PLT从约0.01 V开始，而初始化PLT最后一个样本是真实 `VGS=0、VDS=0.1 V`；同一偏置段列名兼容。
- 原因：电极势垒影响内部势，前缀切换不保证自动重复保存初始点。
- 处理：VGS统一使用 `gate OuterVoltage`；核对列名和偏置后，接入初始化文件的真实零栅压末点，不生成一个人工零电流点。两份来源写入summary。
- 验证：pilot Vth按外加栅压为3.871339 V；真实0 V初点被保留，冻结定电流括区与图件横轴一致；解析/数值测试退出0。
- 边界：不能盲目拼接不同偏置文件；BV的内部漏压与外加栅压口径也不能互换。

## 7. Visual 的默认颜色不等于目标物理量

- 场景：初版电场/掺杂图同时留下默认标量，初次导出视野与后续截图也不一致；切线导出还请求了不存在的正交坐标，产生警告。
- 证据：真实 GUI 与原生图显示问题；安装版 API支持 `list_fields`、`set_field_prop -hide -hide_bands`、目标字段 `-show -show_bands`、`zoom_plot -reset`。横向/深度切线分别实际提供X/Y。
- 处理：逐项关闭已显示字段，再显示真实净掺杂或 `Abs(ElectricField-V)`；导出前重置视野；切线只请求真实存在的坐标。保留原生 PNG 和桌面截图两类证据。
- 验证：pilot真实GUI完成修正，字段列表包含电场、冲击电离、接口态及e/h俘获电荷；修正前后截图保存在本机运行资料。
- 附加失败：手册通用属性列表包含 `title_font_size`，但实际二维图拒绝该1D专用属性；二维按轴范围缩放的尝试也未完成导出。失败截图保留，最终脚本删除这些未验证的美化设置，不把命令输入退出0当作GUI成功。
- 边界：API签名还要核对图维度限制；图例全域峰值包含氧化物，本次硅最大场需从半导体专用PLT字段读取。

## 8. 雪崩积分的几何单位不能省略

- 场景：电流超过BV阈值不等于已经证实雪崩主导。
- 证据：安装版 `GettingStarted/sdevice/BVmethods/BV_SV_vis.tcl` 用 `IntegrSemiconductor ImpactIonization * 1.6e-19 * 1e-12`；本次按精确基本电荷换算。
- 处理：在真实BV两侧样本和最后安全停止点计算生成电流/漏电流比值，同时保留原积分和半导体峰值场及位置，不以视觉色标代替。
- 验证：0/60 krad 的BV括区生成电流与端电流相差约0.03%，有雪崩主导证据；新增真实pilot和分辨率比较测试，共7项全部通过。
- 边界：该 `1e-12` 换算绑定本次µm几何、二维单位深度与AreaFactor；其他归一化必须重新查证，不能用同一因子套全部工程。

## 9. 粗网格成本不能直接外推细化预算

- 场景：主网格4296点，0.7倍尺寸细化得到10905点，并减半扫描步长；预先串行提交了两个端点复验。
- 证据：0细化转移/击穿wallclock为283.25/369.88 s；60细化为247.69/285.59 s。单run仅两器件步骤之和已超过计划8 min上限，虽然后续八run批次2326.20 s仍在2 h总求解预算内。
- 原因：预提交控制没有逐run落实完整8 min检查；粗网格pilot约三分钟的成本不代表细化成本。不能只因退出0就说预算达标。
- 处理：观察偏差时末轮端点已执行，不再追加求解、调参或第三档扩展；记录两个单轮超限，不修改原始时间，也不以SSH断开冒充远端停止。
- 验证：两个端点真实归档均正常完成，数值门槛通过；最终状态另标“单轮预算偏差”，不混同数值失败或全面达标。
- 边界：今后硬预算应在提交控制中按完整run检查并明确可安全终止的对象；本次没有为了这项训练改动共享runner或用户会话。
