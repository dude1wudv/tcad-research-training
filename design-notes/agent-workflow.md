# 长任务分工、交接与验收

复杂任务开始、首次委派及接管时读取本文件。已读且未变化时不重复全文加载；具体实验参数与进度以对应实验目录的计划、日志和运行索引为准。本文件规定协作，不授予新增操作权限；当前用户要求优先，不恢复历史文件中固定模型或一律委派验证的旧约定。

## 1. 职责和读取范围

| 角色 | 负责 | 边界 |
|---|---|---|
| 主代理 | 目标、实验设计、关键接口、依赖、授权、资源安排、整合与验收 | 保留关键判断，可委派核心模块的实现；不必承载全部日志和试错 |
| 执行代理 | 按任务契约调查、实现、排障或运行冻结批次 | 不自行改变实验设计、验收标准、事件清单或预算 |
| 分析代理 | 从已完成的固定归档提取数据、绘图、统计 | 不修改原始数据，不将正在写入的输出当完成结果 |
| 验证代理 | 独立检查获准对象和证据 | 不修改业务代码、配置、依赖；不弱化断言或跳过失败 |

角色按需分配，不要求同时开满。关键路径任务也可委派并等待；共享求解器仍串行，代理并行不代表仿真并行。简单任务直接完成。

执行、调查和审查默认沿用主代理当前模型与推理强度，不自动降级。较长且有交接收益的纯验证可交给一个 `validation_worker`（`gpt-6-luna`、`high`），不可用由主代理接管；不得因此把科学设计交给纯验证角色。配置无法核实时明确标记，不以提示词证明实际模型或OAuth状态，不读取凭据。子代理不再派发；当前环境禁止子代理时不得启动。

按任务读取必要材料：项目定位见 [README](../README.md)，研究规划见 [实验计划](../experiments/plan.md) 与 [路线](../experiments/roadmap.md)，报告任务见 [提纲](../reports/outline.md)；实际执行再读 [操作规范](workflow.md) 和目标实验自己的计划、操作文档及最新日志。PN/VDMOS测试仅作为经验，不能替代DRAM模型或数据。

## 2. 委派契约与所有权

每项任务使用唯一任务ID，交付一个可验收成果。派发包含以下内容，复用已有任务记录即可：

```text
目标与作用：要解决什么，主任务如何使用结果。
输入：必读文件、已确认事实、commit及相关未提交文件哈希/快照。
范围：允许写入的确切文件或独立目录；禁止修改项和资源限制。
决策边界：可自主处理的细节、必须回报的设计变化和停止条件。
验收：必要检查、输出位置和判定标准。
依赖：哪些工作可并行，哪些必须等待该成果验收。
```

工具支持时使用独立上下文和精简任务包；只有不可分离的历史依赖才继承完整对话。省略历史时仍须传递全部相关授权、约束和已知失败。默认模型继承不等于必须继承全部聊天。

每个文件同时只有一个写入者；主代理和验证者不得修改执行代理正在使用的输入。需要更改时先到安全检查点、确认所有权移交，再修改。跨模块共享接口由主代理先定，避免并行实现相互覆盖。

共享求解器、队列及运行索引指定唯一调度者。移交需记录负责人、运行ID、输入版本、输出目录、进程/作业核查方式、已提交清单及恢复入口；确认旧调度者不再提交后才能启动新调度。聊天结束、代理离线、断连或包装进程退出都不能证明求解停止。状态不明只读核查，保护正常作业。

## 3. 回传与主代理理解

中间进度仅回报改变决策的新事实、阻塞、异常或阶段完成；无变化使用工具等待。完整日志和排障过程留在执行侧证据目录，主聊天按需读取关键片段。等待关键路径时，不为保持忙碌创建无价值任务。

最终回报使用以下结构：

```text
状态：完成 / 部分完成 / 阻塞 / 失败。
结果与作用：改变了什么，为什么影响主目标。
证据：关键数值、单位、条件、原始证据位置。
产物与版本：修改文件、输入版本、run ID、哈希。
验证：实际命令、退出码、检查对象及结论。
边界：失败、未做、未验证、残留作业和适用范围。
后续：依赖、下一步及需主代理决定的问题。
```

区分直接事实、推断和假设；不能把计划、命令退出0、归档完成、工程通过和科学有效混写。

主代理采用结果前阅读关键差异和支撑核心结论的原始证据，留下简短验收记录，回答：

1. 结果解决了什么问题、改变了什么行为或判断？
2. 证据对应哪个输入版本、条件和验收标准？
3. 有什么失败、未验证项，不能推出什么结论？
4. 因此下一步可以做什么，还缺什么前置条件？

无法回答时保留“执行完成、待主代理验收”，向原代理定向补证。结果矛盾、版本不符或高风险缺口只阻塞依赖步骤；不能用多个代理意见一致代替证据。按风险最小核查，不重做全量调查。验收记录说明依据和边界即可，不要求记录内部思考过程。

## 4. 状态保存与恢复

优先复用实验的 `plan.md`、`journal.md`、交接记录及现有机器运行索引。主代理维护精简的协调状态：当前目标、有效约束、已验收结论及证据、活动任务/负责人、阻塞和下一步。子代理只更新获准的任务记录。不要擅自在程序读取的索引中添加协调字段或改变其状态语义。

在关键决策、阶段完成、失败或长作业移交时保存状态，不等到压缩前才补写。历史过程保留在日志，通过链接引用；无需为每条命令更新协调摘要。禁止新建一套与现有索引竞争的事实来源。

压缩、重连或接管后，先读最新用户要求、有效指令、当前状态与相关交接，再核对版本、进程、队列及最新输出。摘要只定位证据，不能替代实时核查。状态文件与原始证据冲突时查明原因，不凭记忆补全或自动重跑。

同一问题的补证和复验优先使用原代理；新独立阶段或旧代理积累大量无关历史时，先完整交接再换新代理，不能遗留多个调度者。

## 5. 验证与TCAD判断责任

低风险可逆文档改动只检查差异、引用和一致性；实质行为变更、相关已知失败及项目必要检查不能省略。复用已有验证，通过后仅因新改动、失败或未解决风险追加。失败日志保留，不以合成结果、弱化断言或略去失败充作通过。

主代理必须理解并维护物理假设、初态定义、读出时序、判据、统计分母、停止规则和结论边界。执行代理可落实冻结设计，不能为了收敛或更好结果自行调整参数、判据、事件种子或样本量。

受控初态不是实际写入校准；保持漂移、粒子扰动、判据误读与持久位翻转分别描述。匹配对照、单位、run ID和输入版本必须可追溯。同事件的0/1配对及确定性复跑不增加独立样本；失败、缺失、临界和数值不确定不能隐含计为正确。结论不得外推商业器件可靠性或真实辐射截面。
