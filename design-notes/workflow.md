# 仿真与桌面操作经验

运行、恢复、取证及Git操作前读取本文件；具体命令和参数同时以目标实验的操作文档与冻结计划为准。首次协作或交接另见[长任务协作](agent-workflow.md)。历史操作成功不是当前状态或新增操作授权。

## 1. 已跑通的流程与边界

本项目采用 **Windows 管理工程与版本 → VMware NAT + 严格 SSH → Linux 原生求解 → Sentaurus Visual 桌面核对 → 证据回传**。

已实测：在客户机桌面终端输入 `swb`，启动 Workbench；由 `scripts/tcad.py` 调用 SDE、snmesh、SDevice；在实际 Visual 窗口显示结果并截图。

**没有实测**通过 Workbench 的 Run 按钮执行节点工程。普通 `.scm/.cmd` 文件不是完整 Workbench 项目；不能用空白 Workbench 窗口证明节点调度已成功。

依据：[PN 电场测试](../tests/pn-field-desktop/README.txt)、[结果与图件哈希](../tests/pn-field-desktop/result.json)、[真实桌面截图](../tests/pn-field-desktop/screenshots/03-electric-field-desktop.png)。

## 2. 先保护基准，再修改参数

1. 原始 VM 保留，使用独立磁盘副本；此副本保留硬件身份，不能与源 VM 同时启动。
2. 复制已通过的模型到新的测试/实验目录，不修改基准。
3. 写清参数原值、新值、单位、物理意义及预期观察量。
4. 正式因果比较优先单因素；多参数演示不能用于分辨各参数的独立影响。
5. 冻结本次输入，保存哈希；网格到依赖电学求解串行执行。

本次操作测试同时改了 P 掺杂 `1e16 → 5e16 cm⁻³` 和阳极终点 `+0.5 → −2 V`。它证明流程可执行，不是这两个因素的独立效应研究。

## 3. 环境排障分层，不混淆失败来源

| 观察到的问题 | 本次证据与处理 | 复用注意 |
|---|---|---|
| VM 只有回环地址，网卡 unmanaged | 启用 NetworkManager networking，设置 ens33 托管和自动连接 | 先核对真实网卡名；当前引导脚本专用于此镜像的 ens33 |
| `.solver.lock: Permission denied` | 父目录为 root 所有；同时给科研父目录和 runs 目录设置 tcad 所有权 | 只处理项目拥有的目录，不用全盘递归 chmod/chown |
| `sdevice -V` 不识别 | 此版本实际支持 `sdevice -v` | 依据安装版本帮助，不凭习惯猜参数 |
| 远程命令退出码 255 | 后续原始 stderr 显示 FlexNet `-97,234`、vendor daemon down | 255 不必然是 SSH 传输失败；必须保留远程 stderr |
| 工具曾成功，后来许可不可用 | 正常执行 `lmutil lmreread` 后再次签出/签入成功 | 历史运行通过不代表当前许可仍可用；不改许可证或绕过授权 |
| 早期失败缺少退出码文件 | 将 EXIT trap 和日志重定向放在锁操作之前 | 正常退出已实测；故障注入路径仍未验证 |

具体恢复记录见 [initialization.txt](../records/initialization.txt)。`sdevice -v` 在此镜像会签出许可证，因此 `doctor` 不是纯路径检查。

连接原则：用 VMware Tools 获取实际 IP；专用公钥认证；可信获取并固定服务器公钥；不关闭主机校验、不猜 IP、不开放公网端口。用户有活跃会话时，不为测试随意重启 VM。

## 4. 求解成功不等于科研有效

最低工程验收同时检查：

- 工具、SSH 及归档退出码，不能只看“文件存在”。
- 日志的收敛与完成标志，最终偏压是否真的到达目标。
- `.plt` 数值是否完整、有限，接触命名、符号及端电流是否一致。
- `.tdr` 是否包含所需场变量，是否来自同一 run 的最终解。
- 输入哈希、原始结果归档哈希、准确命令和工具版本。

当前 runner 的 `COLLECTED` 只表示执行/归档成功；不会自动完成上述全部物理检查。单核和项目锁是运行约束，不是数值正确性的证明；锁也不约束其他仓库或手工求解器。

正式科研还需模型适用性、边界条件、网格与步长敏感性、单位和二维电流归一化、基线校准等工作。电流很小或图看起来合理，都不能替代这些检查。

## 5. 桌面显示必须核对变量

- 桌面 GUI 用已登录的客户机用户和 `DISPLAY=:0`；SSH 成功不等于可访问图形会话。
- SDevice 输出请求写 `ElectricField/Vector`；此次 Visual 中实际电场模量名为 **`Abs(ElectricField-V)`**。
- 直接用 `ElectricField` 设置显示失败；Visual 仍显示默认 `DopingConcentration`。所以必须核对**色标名称和单位**，不能仅看彩色图。
- [field.tcl](../tests/pn-field-desktop/field.tcl) 读取最终 TDR，设置电场模量，再用原生 `export_view` 导出。
- 图窗加载成功后再截图；最大化窗口以便看清变量、色标、坐标和工具版本。
- 图像导出和桌面截图各保留一份：前者适合报告，后者证明实际 GUI 显示。两者不是同一种证据。
- 客户机根窗口截图不伪造界面；上传前检查是否包含密码、许可证内容或无关私密窗口。
- 点击坐标只对最新截图有效；窗口移动、最大化后重新截图。用 `xwininfo` 核实窗口 ID，不复用旧 ID。
- 启动或重启本地 SSH 包装进程不保证远端 GUI 随之关闭；操作后核对实际窗口，避免遗留重复视图。

此测试 Visual 色标峰值约 `7.90×10⁴ V/cm`；它是本次模型的结果，不应硬编码为其他器件的验收期望。网格日志的二维单元数与 Visual 包含边界元素的总数不同，不直接比较。

`local_runtime/` 保存：本机连接配置、完整日志、TDR/PLT、原始结果归档。VM、密钥和许可证不入库。提交摘要保留 run ID 和哈希，让“这张图来自哪次求解”可回答。

## 7. 执行约束与授权

以下约束保留原仓库操作边界；不会因改用执行子代理而扩大授权。

### 环境、数据与运行

- 复用 `scripts/` 的现有运行器，不建立并行维护的另一套runner。通过 `python scripts/tcad.py run <工程目录>` 调用真实工具链；每步在 `project.json` 声明预期产物。结构/掺杂/网格、平衡初始化、偏压和结果提取按依赖执行。
- SDevice 保持 `--threads 1 --exit-on-failure`、单核affinity和已有锁；未经设计与验证，不增加并发、不绕锁。锁不覆盖手工求解或其他仓库，因此提交前仍核对活动求解和唯一调度者。
- 使用 `local_runtime/connection.json`；VMware Tools发现目标地址、专用密钥、严格服务器公钥校验。主机指纹变化必须从可信控制台核实，不猜IP、不关闭校验、TLS或配置公网转发。
- VM位于仓库外 `machines/`；不写原始镜像、旧项目或环境基准。副本保留原硬件身份，不同时启动源镜像和副本。不擅自重启、挂起、关机或结束用户进程；会中断用户工作的操作须在明确授权内进行。
- 不擅自安装/升级客户机、TCAD、系统包或未知插件，不将CentOS 7客户机作为公网服务。不读取或修改许可证、时间、硬件标识以绕过许可；正常维护也须在授权内留存准确命令和结果。
- 每次新运行使用独立目录，冻结输入并保存SHA-256、commit、准确命令、工具版本、退出码及原始输出。有未提交修改时，commit不能替代实际内容哈希。恢复既有工况先查进程、远端目录、退出码和归档，禁止盲目重发或覆盖。
- 密钥、密码、OAuth凭据、许可证、VM、受限安装包和商业工具文档副本不得入库。完整日志与大型TDR/PLT归档留在被忽略的 `local_runtime/`；只提升审核后必要汇总和图件，不放开整个目录或强制加入大型成果。
- 保护用户未提交改动、历史实验和失败证据。参数变更必须在授权范围内记录原值、新值、理由及来源；多参数变化不得解释成独立因果效应，不能由拟合曲线倒推出真实工艺结构。

### 验收和图件

- 执行与归档退出码、求解收敛、实际时间终点、有限完整数值、接触名称/电流符号、TDR字段及输入输出来源均须核查；`COLLECTED`只代表工程归档状态。具体守恒、源积分、网格/步长敏感性及初态/读出容差沿用实验冻结契约，不按结果放宽。
- 未校准二维模型、操作测试、课程正式研究分别标注。缺少参数来源时不冒充实验室或商业模型；探索授权不等于教师审核或真实器件校准。题目和评分以[课程大纲](../docs/course-project-syllabus.md)、[实验计划](../experiments/plan.md)和[报告提纲](../reports/outline.md)为准。
- 用户要求桌面操作时必须在真实客户机会话执行并截图。普通deck不是完整Workbench工程，后台求解不能充作Run按钮执行证据；加载目标run的TDR，核对变量、单位、时刻/偏压和色标。
- 原生导出、真实窗口截图、数据生成图分别标注并保存run ID和哈希。禁止伪造界面、实测点或求解日志；截图前检查秘密和无关内容。清理仅限已核实属于本任务的进程和文件，保留用户GUI。

### Git与交付

- 提交、推送、生产操作和秘密处理只由主代理在已有授权内执行；委派或写入文档不是新增授权。未经授权不重写历史、强推或删除无关内容。
- GitHub网络Git命令必须设置 `HTTP_PROXY=http://127.0.0.1:7890`、`HTTPS_PROXY=http://127.0.0.1:7890`、`GIT_TERMINAL_PROMPT=0`。代理失败即停止，不改直连、不绕过代理、不关闭TLS校验。
- 交付列改动、实际命令/结果、证据路径、失败与未做项。必要检查未完成或仍失败不得宣称验收通过；提交成功、仿真成功和科学结论成立是不同状态。
- 通用经验按“场景—问题—原因证据—处理—验证—边界”记入 `design-notes/`，一次运行事实仍放对应实验目录。文档引用唯一实现，不复制维护多套脚本。
